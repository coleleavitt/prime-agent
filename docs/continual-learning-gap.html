Why it cannot learn

The failure ledger, RAVO reducer weights and trust windows live in session state. They exist in 1,251, 41 and 2 of 1,322 session harness files — and in none of the global file. So the counter that recurrence ≥ 2 reads is reset to zero at every session boundary.

The trigger that implements “make an error once, never again” is structurally incapable of firing across sessions. It can only fire twice inside one conversation. Everything the 409 refinements learned is thrown away when the session ends.

And what it does produce is the wrong shape. Sampled triggers: “Store the session-local project fact that…”, “Stored the latest ERS deployment state needed to continue this session safely.” — the refiner believes its job is scratch notes for context continuity. 26 of 27 global memories were written by the agent itself via ctx_memory, not by refinement.

What closes the loop

Five changes. The first is a precondition for the other four.

  1. Promote the failure ledger to global. One file, survives sessions, fingerprints accumulate. Without this nothing else can work — recurrence is reading a counter that is always zero. Smallest possible fix, largest effect.
  2. Replay the failing case as the verifier. Today the deep score is an LLM judge (run-service.ts:92 → "judge" | {kind:"arc-agi"}), so the gate asks a model whether a model's fix is good. Instead: capture the failing trajectory, re-run it against the candidate harness, accept only on a real before/after difference. Your own Rocq development already demands this — Ravo.v §16: FlawUpheld iff an executable test fails; prose is not evidence.
  3. Induce skills, not memories. 553 memory operations, 2 skills. A memory is a paragraph the model has to re-read and re-interpret every turn; a skill is code that either runs or doesn't. When a fingerprint recurs, the correct output is a callable, testable skill.
  4. Every fixed failure becomes a permanent regression case. This is what converts “don't make that mistake again” from a hope into a property. It also gives the verifier in (2) its corpus for free.
  5. Make improvement measurable. Recurrence rate per fingerprint over time is the benchmark, and the trace plane already carries the data. Right now you cannot answer “are we improving?” because the state resets before anything can be compared.

1. The retention window is shorter than any trend

All 157,374 spans fall inside a single 12.7-hour day. Rotation is size-based, so the evidence needed to show a trend is deleted before a trend can form. You cannot chart improvement over weeks because you only keep half a day. Fixing the learning loop without fixing retention would leave you unable to prove the fix worked.

2. Within the window, failures do not decay

Each row is one failure fingerprint; each tick is one occurrence. If the system were learning, ticks would cluster left and stop. They do not.

The damning rows are the wide ones. agent_observe max_chars must be between # and # fires 18 times spread over 675 minutes — the same schema violation, all day, never corrected. Cannot read properties of undefined (reading 'trim'): 5 times over 679 minutes. The OpenWebUI rate limit: 30 times over 622 minutes. By contrast Target session has too many pending messages fires 72 times inside 22 minutes — that one is backpressure, not a learning failure, and the shape tells you which is which at a glance.

3. The counter cannot accumulate anyway

Even with a longer window, recurrence ≥ 2 reads a per-session counter that resets at every session boundary (see above). So the three failures compound: the evidence is rotated away, the ledger is reset, and the gate that would act on it asks a model for an opinion.

This chart is the benchmark you asked for. It costs nothing to keep producing, and after the fixes land the same chart should show ticks stopping. That is what “genuinely improving” looks like as evidence rather than as a claim.

The signal that would close the loop is the one signal it cannot see

This is the sharpest finding of the whole investigation.

core/ravo/failure-ledger.ts:14 — FailureKind = "python_exception" | "tool_error" | "provider_error". Three kinds. A user correction is not one of them. There is no fingerprint for it, so it never enters the ledger, so recurrence ≥ 2 can never fire on it, so it can never trigger a refinement.

And yet core/refinement/refinement.ts:484 — the prompt text handed to the model — explicitly lists “a user corrects behavior that should persist locally or globally” as a reason to call refine.run().

So the system asks the model to learn from your corrections while providing no mechanism to detect one. It depends entirely on the model noticing, mid-turn, that it was corrected, and volunteering. 147 instances of the richest learning signal available — a human saying “no, that’s wrong” — fall on the floor. Success is not attributed either: nothing records that an entry helped.

That is the answer to “what is the problem we are trying to solve”. It is not the gate, not the ledger, not durability — those are downstream. The loop is open at the input.

The doctrine — 48 principles, 8 readers, 355 tool calls

A full sweep of the 54-document research corpus. The synthesis is on disk at docs/cortexkit-doctrine.md — 28 deduplicated principles scored across Claude Code (A), ckl (B) and prime-agent (C). The core claim, in the synthesizer's words:

Mainstream agent design treats the conversation as the system of record: the transcript is the state, a tool call is the work item, “the turn ended” is the completion signal, and one model's opinion of its own output is the gate. That works exactly as long as the process lives, the context holds and a human is watching — and it fails silently the moment any of those stop being true, because every failure mode it has produces a system that looks healthy and is empty.

The finding that reframes RAVO

The real Athena councils ran 8 heterogeneous models (Opus 4.8, GPT 5.6 PRO, GPT 5.6 Terra PRO, GPT 5.5 xhigh, XAI Composer 2.5, Ollama Minimax M3, Ollama GLM 5.2, Gemini Flash 3.5) under the rule “a single un-refuted concurrency defect is a NO-GO.” Three decisive findings were solo — one member each:

  • N7 (Minimax, solo): the shipped RouteBinding has no reference to any dispatcher — “the terminal path holds an Arc<RouteBinding> and literally cannot reach the inbox.” The v2 mechanism was unimplementable as specified and exactly one model noticed.
  • The memory-DoS bound (up to 128 GiB on one route, 256 GiB per connection) — a 3-of-8 minority, computed only by the GPT variants.
  • The one cross-account privilege escalation in the federation review — solo Gemini.

Under majority rule all three are noise. Under this gate all three block. That is the argument for heterogeneity, and it is empirical rather than aesthetic.

Now prime-agent. run-service.ts:1012: “One judge call per proposal, shared by the deep gate and the hygiene opponents.” The five opponents — evidence, scope, minimality, contracts, novelty — are not agents; each is scored purely by whether that one judge listed its id in failedCriteria. So:

RAVO's adversarial structure is a weighting scheme over ONE model's self-report, memoized so it cannot even be resampled.

The synthesizer was explicit that the defect is placement, not competence. core/ravo/archive.ts is an append-only hash-chained log with fsync, torn-final-record repair, a filesystem lock, and a real epoch-CAS in accept() that throws RavoStaleCommitError — better than ckl's equivalent on the repair path. Every correct mechanism above is wired to something other than the learning loop.

Can the agent improve its own kernel? No — and the reason is one missing struct field

You asked whether the REPL or kernel is mutable. The answer is precise:

RefinementEdit (refinement.ts:78-89) has fields title / content / path / reference / arguments / metadata and no field that can carry source code. A skill entry's reference must name an already-importable module, and the RAVO fast screen spawns python -I -c importlib.import_module(mod) — so a proposal to create genuinely new code is guaranteed to fail its own screen.

Which means: 409 refinements can only ever register pointers at code a human already wrote. Confirmation on disk — ~/.prime/agent/skills/ contains exactly one entry, and it is a symlink to an external repo. The agent has never written a durable line of capability.

The good news is that the cross-session half already works and nothing uses it. A directory at ~/.prime/agent/skills/<name>/ with SKILL.md + pyproject.toml + src/ is auto-collected, enabled by default, installed with uv pip install --editable (measured: 400 ms), and bound into globals() at bootstrap. Cells are unrestricted exec into the real __main__. The agent could already write those files today — it has no primitive that does it and no gate that would accept it.

Two latent defects found along the way: validateName (skills.ts:122) checks charset only, so a skill named bash or open is legal and wins the name lookup over rlm.bash and over builtins; and bootstrap eagerly imports every skill inside a try/except, so a skill that blocks at module scope hangs kernel start forever and the except never runs.

  • Distillation / RL — cut outright. Composition kills it before volume does: 74 of 96 fingerprint sources are ipython, and the two biggest classes are AttributeError: ? object has no attribute ? Also: the pairs are ones this same policy already fixed on the next cell, so advantages collapse; and “does not raise E” is reward-hackable with try/except: pass.
  • The ask primitive — keep as product, cut from the learning roadmap. A limit worth recording

Claude Code redacts chain-of-thought at rest. Of its 1,542 thinking blocks, 2 carry recoverable text (0.1%, 509 characters total); the rest keep only an encrypted signature. Human correction, for contrast

1,497 instances, and the distribution is blunt: redirect 53% (“instead”, “I meant”), revert 22%, flat-no 14%, slop 9%. Only 1.2% is an explicit “that's wrong”.
