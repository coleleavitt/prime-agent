## 1. THE CORE CLAIM

Mainstream agent design treats the conversation as the system of record: the transcript is the state, a tool call *is* the work item, "the turn ended" *is* the completion signal, and one model's opinion of its own output *is* the gate. That works exactly as long as the process lives, the context holds and a human is watching — and it fails silently the moment any of those stop being true, because every failure mode it has (lost effect, double effect, a judge that never answered, a memory that was never re-read) produces a system that looks healthy and is empty. The claim is that an agent is not a loop but a **durable organization**: admission precedes effect, every durable write is epoch-fenced, every non-advance is classified and recorded, the output contract is decided by a parser rather than a model, and the gate is a plural, archived, re-derivable panel — and that without those, a learning loop is not a learning loop, it is an evolutionary search with the fitness signal disconnected.

## 3. WHERE EACH SYSTEM STANDS

**A — Claude Code / mainstream tool loops.** Almost every row is `N`, and in A's own frame that is not a criticism. A optimizes for a human-supervised session measured in hours, where the human *is* the recovery mechanism, the *escalation* channel and the *verify leaf* — row 26 is the one place A beats C outright, because the human is present at every turn by construction even though nothing types it. Its real virtues are legibility (one state: the transcript), zero plumbing between decide and do, and no stale-derived-state bug class at all. Row 24's `~` is honest but borrowed: exactly-one-result-per `tool_use_id` is enforced by the provider rejecting the next turn, not by the harness. The failure is that every one of A's virtues is a statement about a process that is still running with its context intact, and A has no vocabulary for the moment that stops being true.

**B — ckl.** The foundations are real and tested, not asserted: `ckl-lease`/`ckl-store` give a persisted epoch and `with_conn_fenced` CAS with `store_ahead` refusal; `ckl-prefrontal/src/recovery.rs` classifies into `not_sent` / `not_sent_adopted` / `launched_no_link` / `resumable` / `paused` / `idle` / `pending_finalize`; `crates/ckl-prefrontal/tests/kill_test.rs` plus `src/killpoints.rs` kill a real process at four marked points; `ckl-mc` runs the upstream `cortexkit-cache-core` golden vectors (schema 3, 11 vectors) rather than a hand-port; `ckl-athena/src/council.rs` does nudge-once-then-exclude with a printed denominator and quorum-cancels retries; and — the row almost nobody else gets — `docs/PLAN.md` carries a *Deliberate stubs* section that labels `nudge cap 3` and `grade threshold 80` as `[GUESSED]`. The Rust crate graph makes row 28 enforceable rather than aspirational. What B does not have is the thing the whole substrate exists to carry: `grep -rln "refine\|self-improve\|skill_induction" crates/ --include=*.rs` returns **nothing**. `ckl-mc` can store a memory, watermark it and fold it; nothing in ckl ever proposes a change to ckl's own behavior, and nothing measures whether a change helped. Add to that: the exit tests are self-authored, the evidence base is a leaked corpus that B itself grades MEDIUM in places, and there are no users. B is a flawless chassis with no engine and no odometer.

**C — prime-agent.** It ships, it has users, and it contains the single best piece of durability engineering in either tree — `core/ravo/archive.ts` is an append-only hash-chained log with fsync at :216/:247/:307, torn-final-record repair, a filesystem lock, and a genuine epoch-CAS in `accept()` that throws `RavoStaleCommitError` when `state.revision !== expected.revision || state.championDigest !== expected.championDigest`. That is *better* than ckl's equivalent on the repair path. `modes/daemon/command-recovery-journal.ts` is an independently reinvented three-phase durable intent log (`ReceivedRecord` → `ResultRecord` → `AcknowledgedRecord`, `openSync/writeSync/fsyncSync/renameSync`, keyed by `createCommandIdempotencyKey`) — that is `record_intent` → `mark_launched` → `link_execution` built by hand, correctly. `daemon-mode.ts:562` `promptAdmissions` is a real per-correlation slot with duplicate rejection and three cancel outcomes. `ravo/retained-worker-runtime.ts:283-291` `applyScope` is a genuinely monotone-narrowing per-worker tool allowlist. `RavoGateCertificate` (`ravo/reducer.ts:107-122`) is "a deterministic, JSON-compatible witness for every gate decision," carrying `rejection?: RavoRejection`. The defect is not competence; it is *placement*. Every correct mechanism above is wired to something other than the learning loop. Measured directly: `/home/cole/.prime/agent/harness/harness_state.json` is 75.4 KB, `schema: 1`, 27 memory entries, **0 prompt, 0 skill, 0 subagent**, `refinements: 1`, and carries neither a `failures` nor a `ravo` key; `refinements.jsonl` is **1 line**. Across 1,322 session-scoped `harness_state.json` files: **409 refinements**, 342 memory entries, **2 skills**, 41 carrying `ravo`, and **1,251 carrying a `failures` ledger that has reached the global file exactly zero times**. The learning loop runs, decides, and writes into a container that is destroyed at every session boundary.

## 4. THE SYNTHESIS

**B and C are the same system cut in half, and each half is uninteresting alone.**

C's loop is not broken; it is *ungrounded*. Trace the four things an evolutionary search needs and where each one dies in C:

1. **A genome that persists.** `refinement/refinement.ts:372-386` is `writeFileSync` + `renameSync` over one JSON blob with no fence and no fsync, while `:349` does `merged.schema = Math.max(globalState.schema, localState?.schema ?? 1)` (an older binary adopts a newer schema and rewrites it in its own shape) and `loadHarnessState` catches every parse failure into `emptyHarnessState()` — a closed shape that drops every top-level key the binary does not know. A daemon, N resident session workers and a live IPython kernel that can call `rlm.harness.create_memory(...)` mid-pass are three concurrent writers to that file.
2. **A fitness signal.** `run-service.ts:554-568` `certificateSummary` keeps `{proposalId, status, screenScore, deepScore, missed[]}` and discards every per-criterion `detail`; the `/refine` reject branch (`agent-session.ts` ~9270-9302) appends to session JSONL and returns — no archive event, no reason, and `appendGlobalRefinement` is called once, at `:9337`, guarded by `targetScope === "global"` on the **accept** branch only. 56% of every evaluation the gate ever made is unrecoverable.
3. **Selection pressure.** `failure-ledger.ts:61` `DEFAULT_RECURRENCE_THRESHOLD = 2` counts "in this session" (`:442`, the harness's own prose), `_flushFailureLedger` writes only to `_localHarnessStateDir()`, and the cursor at `agent-session.ts:8401-8404` is a bare integer over the active branch clamped downward on rewind. A failure that happens once per session, forever, never reaches 2.
4. **An outcome test.** `refinement/ravo.ts:39-43` describes exactly the right one — the provisional-commit observation window, "judge said pass, outcome said fail" — and it is measured against the ledger in (3), so it structurally cannot fire.

B has a correct, tested implementation of (1), (2) and (4), and does not need (3) because it never proposes anything. **The port is not an architecture transplant; it is moving four mechanisms from the crate that has no use for them into the module that is starving for them.**

Specifically, what crosses:

- `ckl-store::with_conn_fenced` epoch-CAS + `store_ahead` refusal + per-namespace migration chains → the harness store's write and load path. C already proves it can do this: `ravo/archive.ts:131-145` *is* this, applied to the per-session archive rather than to the file that carries behavior.
- `ckl-prefrontal/src/dispatch.rs` two-phase + `recovery.rs`'s `RecoveryReport` classes → the refinement apply path. C already has the shape in `command-recovery-journal.ts`; it is confined to the daemon command path and absent from the learning path.
- `crates/ckl-prefrontal/src/killpoints.rs` + `tests/kill_test.rs` → a prime-agent test that `kill -9`s the session worker between propose and apply. C's central product claim has no test; ckl's central claim has exactly one, and it is this.
- `ckl-mc/src/memory.rs` (`list_since(watermark)`, advance-only `set_watermark`) and `decay.rs` → `formatHarnessStateForPrompt`, replacing `DEFAULT_OVERVIEW_ENTRY_LIMIT = 6` against 27 entries sorted by `[a.path, a.title, a.id].localeCompare(...)` (`refinement.ts:498`).
- `ckl-mc/src/classify.rs`'s ordered first-match `PassPlan` + the golden-vector fixture → the eight uncoordinated `_rebuildSystemPrompt` call sites in `agent-session.ts` (1618, 1647, 1707, 1973, 4630, 9352, 9805, 12733), each of which busts a prefix that `providers/anthropic.ts:966-982` marks `cache_control`.
- `ckl-athena`'s injected `CouncilLauncher` trait + `extract.rs`'s two-bit extractor + quorum/exclusion → the RAVO gate, which C can afford because it already launches real heterogeneous children (`run-agent.ts`, `retained-worker-runtime.ts`, `core/model-registry.ts`) — where `run-service.ts:1012`'s `memoizedJudge` currently makes the panel un-resamplable at N=1.

And what C gives B, which is the larger half: ckl's council is a gate with nothing behind it, and RAVO is the thing a gate is *for*.

## 6. WHAT NOT TO PORT

1. **Do not port `ckl-lease::acquire_exclusive` to the harness store.** ckl is one daemon over one sqlite file; prime-agent runs a supervisor plus N resident session workers plus a live IPython kernel that can call `rlm.harness.create_memory(...)` mid-pass. An exclusive lease over the global store either serializes every worker's prompt rebuild behind one lock or fails the second worker's startup with `LeaseError::Held` — in a product whose stated doctrine is that closing the TUI must never stop an agent, that is a regression. Port the **epoch CAS** (`with_conn_fenced`, and H0's `revision` field); do not port the **exclusivity**. The fence makes a lost update *detectable*; the lease makes concurrency *impossible*, and prime-agent needs the concurrency.

2. **Do not port sqlite.** `grep -rln "CREATE TABLE|better-sqlite3|node:sqlite" packages/*/src/` returns nothing today, and that is not an accident worth fixing by force: `engines` is `node >= 22.8.0`, where `node:sqlite` still requires `--experimental-sqlite`, and `better-sqlite3` is a native module that has to survive `check:installer` and npm distribution. The invariants port; the engine does not. You already own a better substrate for them than sqlite would be — `ravo/archive.ts` does hash-chained append, CAS, fsync and torn-record repair, and generalizing *it* is a smaller change than adopting a database.

3. **Do not port worktree-per-subagent.** ckl's subagents are headless dispatches against a work graph. prime-agent's children share a persistent IPython kernel whose cwd, imported modules and open handles *are* the session, and the product's premise is that the user watches work happen in the user's own tree. Per-task worktrees break the kernel's filesystem identity and the thing users are paying for. What does port is narrower and lands in H3: **a worktree for the replay verifier**, because re-running a recorded failing case is precisely the workload that must not touch the live tree.

4. **Do not port the opaque-byte router rule to `daemon-protocol.ts`.** ckl's thin core buys separability for a system that will one day split the daemon from the executive. prime-agent's supervisor parses `session_snapshot_begin/_chunk/_end` and reconstructs assistant deltas because resumable client attach is a *feature* — a TUI reconnecting mid-turn needs the supervisor to understand the stream, and making the body opaque moves that reconstruction into every client including third-party ACP ones. The rule that does port is the narrow one: a new capability should not force a `DAEMON_SCHEMA_REVISION` bump unless the **supervisor** must understand it. Revisions 21-29 are mostly additive pass-throughs behind capability gates and could have been registrations.

5. **Do not port ckl's `[GUESSED]` constants.** `nudge cap 3`, `grade threshold 80`, `MIN_RESPONSE_LENGTH`, the 30-second deadline floor — ckl's own `docs/PLAN.md` labels these clean-room fills for holes the leaked corpus never closed. Importing the numbers launders a guess into prime-agent as though it were measured, which is the exact failure the doctrine exists to prevent. Port the **register**, not the rows — and put prime-agent's own three unlabelled guesses in it: `RAVO_DEFAULT_CONFIG = { screenThreshold: 50, epsilon: 1, deepTolerance: 10 }` (`refinement/ravo.ts:94-98`), of which only `deepTolerance` currently has a stated reason.

6. **Do not port "never invent a comparator" as a blanket prohibition.** ckl refuses to rank because the corpus marks urgency scheduling a GAP and ckl has no telemetry of its own. prime-agent has 1,322 session state files, 157,374 spans and a failure ledger — it can **measure** an eviction comparator rather than invent one. The doctrine is "never invent an *unevidenced* ordering," not "never order." H4's importance score must ship *with* its usage counter and must not precede it; a hand-tuned weight vector shipped before the counter would be exactly the invented comparator ckl is right to refuse.

7. **Do not port ckl's council roster shape.** Eight members, eight intents, and a `meta.yaml` byte-identical to a leaked schema are artifacts of B being a faithful reconstruction. Byte-compatibility with someone else's `meta.yaml` is worth nothing here, and eight members against 244 proposals is cost with no matching return. Port the three load-bearing properties only — heterogeneity across vendors, exclusion with an adjusted denominator, one-blocker-blocks — at N=3, behind the existing `screenThreshold` so the panel runs only on proposals that already passed the cheap screen.

8. **Do not port "Solo Analysis Mode" as a read-only tool allowlist.** You have a real allowlist primitive — `retained-worker-runtime.ts:283-291` `applyScope` intersects requested with granted and never widens — but if `ipython` is in the granted set the kernel is arbitrary code execution, so the allowlist cannot express "read-only." The property that actually matters is that the member reads the source itself rather than the author's prose (today `judgeSpec` renders a pre-built `BoundedContextView` into the prompt and gives the child no tools at all, which is the same defect mirrored). Get it with a fresh kernel in a throwaway worktree or a read-only mount, not by subsetting a tool list the kernel makes meaningless.

9. **Do not port the human verify-leaf into the interactive path.** ckl is headless, so a node that blocks on a human stamp is the only way work can stop and wait. prime-agent's premise is the opposite — work continues with no human present — and a blocking leaf reintroduces exactly the wedge the daemon exists to remove. What ports is the **record**, not the block: a durable, addressable `escalated` terminal with a declared default decision and veto window, so the agent proceeds under a recorded policy and the fork is queryable afterward. That is a row in H1's decision log, not a new state in the goal machine.
