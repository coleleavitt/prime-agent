- Dream-RSI selection now scores candidates only on the trees the current policy replays in full support (the measured pool). A tree another policy grew, on which the incumbent's replay reveals almost nothing and burns out-of-support rounds, is no longer a baseline: a candidate cannot pass the quality guard on a fictional gain there while regressing on the incumbent's own trees, and cannot win merely by burning fewer dead rounds on it. `PolicySelection`, `DreamResult`, the dreaming round record, the dreams log step line and the `dream.dream` / `dream.replay` spans report `measuredTrees`.
- `dream.quality_rejected` (and `PolicySelection.qualityRejected`, printed by `dream improve`) now counts exactly the candidates whose verdict is `quality-rejected`; an off-support quality failure is `unmeasurable` only, so the span categories sum to the candidate count. `dream.simulations` on `dream.replay` is the exact number of replays the selection made, and the lever scan's count is on `LeverScanRecord.simulations` / `dream.lever_simulations`.
- `prime-agent dream --n` is threaded to every task that takes a size (autocorrelation as well as circle-packing); a size the task does not accept is a usage error naming the accepted values, and the run's size is recorded on the result, the tree headers and the header line for every sized task.
